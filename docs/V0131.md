# 0.13.1 · 降低实时更新的服务器开销

2026-11-17 在 1 vCPU / 约 1 GB 内存的服务器上排查到 QuantPilot CPU 占用偏高，部分采样同时出现交换空间写入。25 秒运行热点采样显示，频繁打开/关闭 SQLite 连接、重复读取配置、反复创建行情线程池是主要应用开销；AI 进程不是主要 CPU 来源。

本次修改：

- 数据库只在首次创建时用文件 API 打开；已有数据库交给 SQLite 管理，避免重复初始化释放进程文件锁。服务启动不再创建多余的 Store。新增跨进程文件锁回归测试。
- SQLite 连接独占借用、事务提交或回滚后复用，空闲池最多 8 个，每连接缓存上限约 512 KiB。嵌套和并发事务仍使用不同连接；每次读取都查询数据库，没有给账户、授权或风控状态添加过期缓存。
- 合并同一快照所需的配置读取。网页订阅目录每秒核对，行情、账户和仓位的推送周期不变。
- 已收到新鲜 WebSocket 报价时，不再重复运行行情扫描；补读线程池复用，持仓保护和执行检查继续运行。
- 账户显示估值由统一发布器处理，避免快速循环重复计算；没有网页订阅者时跳过仅用于网页的估值发布，服务器行情订阅与交易保护继续。
- Gate、OKX 客户端只加载永续合约目录，避免载入本工作台不使用的现货、交割和期权目录。独立外部证据来源不受此目录设置影响。
- 服务升级时给长连接设置退出期限，减少等待旧连接造成的重启拖延。

验证：605 项自动测试通过，语句覆盖率 84%；增加连接池独占、外部提交立即可见、回滚隔离、批量读取、热路径不重复获取行情和无浏览器场景测试。Python/安装脚本检查通过。修改后的 Binance、OKX、Gate 公共币本位行情连接已实测；当前生产服务器的币安地区限制仍保持明确报错。

CPU 和推送的服务器前后对比另存交付报告。测量结果受市场更新量、用户在线数量和其他服务负载影响，不作为固定性能保证。交易设置、评估周期、推送合并窗口和实盘执行门槛保持原有约束。
