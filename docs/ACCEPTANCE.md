# 执行组件验收门槛

0.3.0 已实现订单组件，但没有实际交易所账户凭据，也没有完成交易所测试网联调或独立安全审计。本版交付和生产升级均保持真实下单关闭；不能把自动测试替身的通过写成交易所认证。

## 环境隔离

- `paper`：本地虚拟资金，不请求交易所私有订单接口。
- `demo`：使用 CCXT 对应交易所 sandbox 配置和单独测试密钥；还需进程环境 `QP_DEMO_EXECUTION=1`。测试密钥与生产密钥不可混用。
- `live`：需 `QP_LIVE_EXECUTION=1`、与当前账户和代码版本绑定的限时验收记录、网页账户启用及品种授权。AI 与网页都不能写入服务环境或验收记录。
- 只支持线性 USDT 永续、逐仓、单向持仓。未知/外部仓位阻止新增风险。新建账户、重启、发生执行异常后不自动恢复交易。

## 必须实际完成并保存证据

对 Binance、OKX、Gate 分别执行，保存脱敏请求、订单编号、测试环境截图和账本结果；测试网不支持的功能不得标为通过。

1. 测试账户连通、最小合约数量和金额、逐仓杠杆、单向模式、拒单/限频。
2. IOC 零成交、全部成交、部分成交；使用真实成交数量建立保护。
3. 原生止损在应用停止时仍有效；两档只减仓止盈数量/比例正确，不反向开仓。
4. 止盈后剩余仓位保护、保护单被取消/过期、保护安装失败时的只减仓退出。
5. 网络丢失、未知回执和程序重启，验证不重复发送开仓/加仓；交易所余额/仓位/开放订单核对。
6. 亏损上限、相关敞口、强平距离、行情过期、AI 拒绝/超时、突发风险和停止开仓。
7. 外部人工更改仓位/订单后锁定；原生保护单清理和人工接管。
8. 独立代码审查及足够时长的模拟观测，核对真实账户风险限额和权限。

管理员验收记录位于数据目录 `certifications/<account_id>.json`，权限 0600。代码检查版本 `0.3.0`、交易所、当前凭据 JSON 的 SHA-256 指纹、7 天以内的 `verified_at`，以及 `sandbox_fill`、`native_stop`、`partial_take_profit`、`reduce_only`、`reconnect_reconcile`、`timeout_no_duplicate` 均为真。记录由完成实际验收的管理员签收；系统不会根据单元测试自动生成。此机制不防御能修改主机代码的管理员。

## 异常处理

`sending` / `unknown` 订单以及 `v2_execution_blocks` 保存在数据库中。点击“读取与核对”只读查看账户，不清除锁定，也不会重试订单。发生锁定时在交易所核对仓位、未完成订单和原生保护，先备份数据库，再由管理员根据证据处理登记状态。当前不提供网页“一键忽略错误”入口。

行情中断时不按旧价格模拟退出；已有交易所原生保护留在交易所。原生保护检查失败时冻结自动动作；无法确认的执行必须人工处理。验收过期/执行开关关闭后应用不再发送私有订单，交易所已有原生保护不会因此撤销。

以上事项未完成前，请仅使用本地模拟账户或账户只读查询。
