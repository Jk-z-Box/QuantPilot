# 量化逻辑与设置（0.5.0）

## 量化逻辑

页面分为运行规则、参数、AI 复盘、复盘记录和版本存档。可编辑快速/慢速 EMA、RSI 周期、成交量门槛倍数、ATR 止损倍数、两档止盈的风险倍数及第一档平仓比例。修改会真正影响多周期计算、评分与交易计划，不是仅保存说明文字。

参数均有范围校验；固定 100 分的评分构成、行情时效、价差、事件风险、账户授权、风险预算和服务端实盘门槛不能由 AI 修改。市场页的“有效分数”用于交易机会，量化逻辑页的“合格分数”用于策略复盘，两者独立。

保存、AI 优化、导入和恢复均使用同一事务：验证当前版本 → 备份旧版本及其最近可用评分、截至修改时的净盈亏指标 → 应用新版本 → 清除旧信号和 AI 缓存。另一页面已经改过版本时拒绝覆盖，避免丢失修改。旧版本持仓继续接受保护，不允许用新版本信号加仓。

## AI 复盘与自动优化

1. 在“数据与 AI”连接并保存模型，支持现有 API Key、服务器 ChatGPT 登录和旧版官方授权通道，不会静默切换到付费 API Key。
2. 在“量化逻辑”设置合格分数（默认 75）、间隔（默认 24 小时，1–168）、最少完整交易数（默认/最低 20）和统计窗口（默认 90 天，7–365）。
3. 勾选“启用定期复盘”，可独立选择“低于合格线时允许自动优化”。两项默认关闭。手动“立即复盘”在后台执行，网页轮询结果，不需要等待长请求。
4. 分数达到合格线：保留参数，定期复盘继续运行。后续低于合格线：再次评估优化；只有打开自动优化、存在有效参数建议且通过检查时才应用。
5. 每个参数每次最多改变 20%，两次自动优化至少间隔 24 小时。存在受管交易所仓位、已知外部仓位、待核对订单或交易所账户自动交易时不自动修改参数。AI 不能改账号、密钥、杠杆或开仓资金配置。

AI 请求包含当前参数、规则说明、匿名净收益汇总及最多 100 条完整交易结果（品种、方向、开平仓时间、平均入场价、最后退出价、币数量、加仓次数、退出原因、净收益）。没有管理员密码、API 密钥或账户名称。AI 评分是启发式评价，不是胜率。优化仅代表参数建议通过结构与变化幅度检查，不代表经过历史回测或证明未来盈利。

**样本口径**：本机当前逻辑版本、当前风险偏好及机会门槛下，使用真实行情的本地模拟完整交易。开仓/加仓/分批平仓合并为一笔，完全退出才计数；净收益包含进出手续费、滑点及已有的模拟资金费估算。未平仓、重置掉的仓位、合成演示行情、无版本标识的历史记录、未核对的交易所收益不参与评分。交易所真实收益归集与回测不在本版内。新版本重新积累样本；不足最低笔数时记录“样本不足”，分数为空，不调用模型编造收益评分、不自动优化。

盈利因子 = 盈利交易净收益合计 / 亏损交易净损失绝对值合计；盈亏比 = 平均盈利 / 平均亏损。没有亏损样本时两者显示空值，不记录无限大。最大回撤按已完成交易净收益累计曲线计算，不是浮动权益回撤。

复盘日志最多保留 500 次，每次记录版本、时间、分数、当时合格线、评估配置、净收益、盈利因子、盈亏比、笔数、原因与优化结果。修改或断开 AI 身份会暂停策略自动复盘/优化，避免新身份继承授权。

## 存档和迁移

- 存档上限默认 20，允许 1–100；当前生效版本不占名额。超出时剔除最旧的存档，缩小数量前界面会提示影响。
- “导出策略与存档”下载 `quantpilot-logic-v1` JSON，包含当前参数和受保留数量限制的旧版本、评分及当时指标。文件不包含凭证、账号、数据库或自动运行设置。
- 新服务器安装后，在“量化逻辑”导入文件。导入前自动备份新服务器的当前参数，再建立新的本机版本。外部历史指标标记为仅供参考，不成为本机自动优化的交易证据。
- 导入不修改当前备份数量、合格线或自动化开关；这些需要在新服务器自行设置。文件最多 1 MiB，并对结构、字段、参数范围进行校验；不执行任何导入代码。
- 恢复存档同样先备份当前版本，不会覆盖交易记录。需要完整服务器迁移时仍使用 `sudo qp backup` 并按部署手册保管主密钥和凭据备份；策略导出不是整机备份。

## 设置

修改用户名/密码需要输入当前密码；新密码 12–256 字符，留空只改用户名。修改后撤销所有会话，重新登录。错误验证限制为每来源 15 分钟内 5 次。网页刷新间隔支持 3–60 秒，不影响后台行情与仓位保护频率。

网页更新仅供 Linux/systemd 安装使用，固定信任 `Jk-z-Box/QuantPilot` 的 `feat/mission-control-v2` 开发分支。检查 GitHub 最新提交中的版本元数据，只有更高语义版本可更新；显示拟安装的完整提交对应的短标识。用户再次输入密码后生成有限 JSON 请求。Web 服务没有 shell/root 权限；独立 root timer 每分钟读取请求，重新确认它仍为可信分支 HEAD，校验提交格式、文件所有者/类型/大小/时效后才执行固定仓库的提交锁定安装脚本。

更新必须暂停自动交易、没有已知仓位及待核对订单。后台再次检查并持久化暂停开仓；安装前数据库备份，调用现有依赖锁定、Codex 隔离环境检查与失败程序回退。更新后开仓仍暂停。若失败请检查：

```bash
sudo systemctl status quantpilot-update.timer
sudo journalctl -u quantpilot-update
sudo less /var/lib/quantpilot-maintenance/install.log
```

日志只有 root 可读，网页仅显示固定状态消息。首次安装后更新服务约一分钟就绪；非 Linux 本地开发环境仅能检查版本，不能触发系统安装。当前监听地址和域名只读展示，网络和 TLS 修改仍通过部署流程，避免误改导致无法登录。
